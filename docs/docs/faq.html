FAQ

Short answers to the questions that come up most.

Is MuffinEMU the same thing as Muffin?

No — it is its own emulator now.

MuffinEMU grew out of Muffin (kiddreads/cemu-ios-muffin) but has its own bundle identifier (com.kiddreads.MuffinEMU), its own Cemu core, and its own releases. It installs next to Muffin rather than replacing it.

Do I need to own a Wii U?

For encrypted retail games, yes.

You need keys.txt dumped from your own console. Homebrew does not need it. MuffinEMU ships no keys, derives no keys, and has no way to obtain a key it was not given.

Which install method should I use?

SideStore, AltStore or LiveContainer for a normal install; TrollStore or a jailbreak for embedded JIT entitlements.

See Installation for the full breakdown of which IPA goes with which installer.

Does it support every Wii U game?

Not confirmed — broad compatibility has not been systematically tested.

Not confirmed on hardware

MuffinEMU boots real titles from an imported library on real hardware. A full, confirmed playthrough of a retail title on this exact build is still pending, and this documentation will say so plainly the day one lands.

Can I use a physical controller?

Basic controller input works, but has not been systematically tested.

It has not been exercised across MFi and Bluetooth controllers the way the on-screen pad has.

Is there a paid version?

No. There is no StoreKit purchase in the app at all.

A free code unlocks 3 "Pro" app icon themes. Every other feature — save states, graphic packs, DLC/update import, all 28 non-Pro themes, Melo-Controller, all 20 controller skins — is free with no gate. See Themes & Icons.

What license is MuffinEMU under?

The IPA as a whole is distributed under GPL-3.0.

MuffinEMU's own source is MPL-2.0, like Cemu and MeloCafe. Because Melo-Controller (GPL-3.0) is linked into every build — whether or not its toggle is on — a MuffinEMU IPA as a whole is GPL-3.0, with the MuffinEMU repository as its source.

Does dual-screen TV output work?

Not confirmed yet.

The code path is written against the real display API but has never been exercised with a second display actually attached — see External display routing.

Where do I report a bug?

github.com/kiddreads/MuffinEMU/issues

See Troubleshooting for what to attach.
