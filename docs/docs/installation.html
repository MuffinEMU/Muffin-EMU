Installation

Two sources, because the two install paths need different builds. iPhone and iPad, iOS 15 or later.

MethodFileSigningJIT entitlements
SideStore / AltStore / LiveContainer MuffinEMU.ipa Re-signed with your own Apple ID at install Stripped by the re-sign — use StikJIT or SideStore/LiveContainer's own JIT attach instead
TrollStore / jailbroken MuffinEMU-fakesigned.ipa Ad-hoc signed, no certificate or team ID Embedded in the IPA itself

SideStore / AltStore / LiveContainer

These re-sign the app with your own Apple ID at install, so they take the plain unsigned build.

Add to SideStore Add to AltStore
https://kiddreads.github.io/MuffinEMU/apps.json

TrollStore / jailbroken

Takes the ad-hoc signed build, with the JIT entitlements actually embedded — which is what a JIT enabler needs to give the recompiler executable memory. A SideStore re-sign would strip them, which is why this is a separate source.

https://kiddreads.github.io/MuffinEMU/trollstore.json

Or grab MuffinEMU-fakesigned.ipa directly from the latest release.

Which file is which? MuffinEMU.ipa is unsigned on purpose — the installers above re-sign it themselves. MuffinEMU-fakesigned.ipa is ad-hoc signed, which most tools will still describe as "not signed" since ad-hoc signing has no certificate or team ID. That's expected, not a fault.

MuffinEMU uses its own bundle identifier (com.kiddreads.MuffinEMU), so it installs next to Muffin rather than replacing it. Every build of main is published as a numbered release, going up by 0.1 — after .9 comes the next whole number: 1.0, 1.1 … 1.9, 2.0.

JIT requirements

The AArch64 recompiler needs two things at once: a JIT enabler attached (StikJIT, or the JIT attach that SideStore or LiveContainer itself provides) and the recompiler switch on in Settings > CPU. Without both, MuffinEMU automatically falls back to the multi-core PowerPC interpreter instead — and Settings always says which one a given launch actually got, and why, rather than failing silently.

If a game glitches, desyncs or crashes, Settings > CPU has a "Favour accuracy" option — slower, but worth trying before assuming something else is wrong. Restart the game after changing either CPU setting.

Keys.txt

Real Wii U games ship encrypted. Encrypted games need the keys.txt dumped from your own Wii U — MuffinEMU ships no keys, derives no keys, and has no way to obtain a key it wasn't given. Homebrew is unaffected either way.

Drop it into the keys folder MuffinEMU creates in the Files app (under the app's own name, since file sharing is enabled), or import it from Settings. A file dropped in mid-session is picked up before the next key read — no relaunch needed.

MoltenVK

The Vulkan renderer can use MoltenVK 1.4.3 (the default) or 1.2.8, the build 64Touch uses (Settings > Graphics). The choice applies on the next launch. Metal, the default renderer, does not use MoltenVK at all.

Building from source

CI is the build — .github/workflows/build-ios-app.yml runs the whole thing on a macOS runner. By hand, on a Mac with full Xcode:

git clone --recursive https://github.com/kiddreads/MuffinEMU.git
cd MuffinEMU
cmake -S . -B build-ios -G Ninja \
  -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_SYSROOT=iphoneos -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=15.0 -DVCPKG_TARGET_TRIPLET=arm64-ios \
  -DBUILD_HEADLESS_DYLIB=ON -DCMAKE_MACOSX_BUNDLE=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-ios --target CemuBin
mkdir -p build-ios/out && cp -R "$(find build-ios bin -type d -name Cemu.framework -not -path '*/CMakeFiles/*' | head -n1)" build-ios/out/
cd src/ios && xcodegen generate
xcodebuild -project MuffinEMU.xcodeproj -scheme MuffinEMU -sdk iphoneos -configuration Release CODE_SIGNING_ALLOWED=NO build

The bridge and its glue compile into Cemu.framework together with the core, against the core's own headers. The Xcode app compiles Swift only and embeds that framework.
