Installation

iPhone and iPad, iOS 15 or later. There are two builds, and picking the wrong one is the most common install problem — so start with which installer you use.

On this page

  • 1. Pick your build
  • 2. Install it
  • 3. Turn on JIT
  • 4. Add keys.txt
  • MoltenVK
  • Building from source

1. Pick your build

Two IPAs are published with every release, because the two install paths need different builds. Pick the row that matches how you install apps.

SideStore / AltStore / LiveContainer

MuffinEMU.ipa

  • Re-signed with your own Apple ID at install.
  • Unsigned; the installer signs it.
  • JIT entitlements are stripped by that re-sign, so you attach JIT separately with StikJIT, or SideStore's or LiveContainer's own JIT attach.

TrollStore / jailbroken

MuffinEMU-fakesigned.ipa

  • Ad-hoc signed — no certificate, no team ID.
  • JIT entitlements are embedded in the IPA itself.
  • Some tools call this "not signed". That is normal for an ad-hoc signature.
Why two files

SideStore re-signs at install and removes JIT entitlements, so it needs the unsigned build. TrollStore keeps them, so it gets the ad-hoc signed build.

2. Install it

SideStore / AltStore / LiveContainer

Add to SideStore Add to AltStore

Or add the source by hand: https://muffinemu.github.io/MuffinEMU/apps.json

TrollStore / jailbroken

Add the source: https://muffinemu.github.io/MuffinEMU/trollstore.json

Or download MuffinEMU-fakesigned.ipa directly from the latest release.

Nightly builds

Want the newest build instead? Nightly sources: https://muffinemu.github.io/MuffinEMU/nightly.json (SideStore, AltStore, LiveContainer) and https://muffinemu.github.io/MuffinEMU/nightly-trollstore.json (TrollStore). Nightly builds are untested and replace a standard install.

Experimental builds (for testers)

Unfinished test builds of work in progress, published by hand. Experimental sources: https://muffinemu.github.io/MuffinEMU/experimental.json (SideStore, AltStore, LiveContainer) and https://muffinemu.github.io/MuffinEMU/experimental-trollstore.json (TrollStore). Every experiment is listed as its own version, newest first. Each one replaces an installed MuffinEMU (same bundle identifier, so your games and saves carry over) and can misbehave; they never appear in the standard or nightly sources. For normal play use the standard source.

MuffinEMU uses its own bundle identifier (com.kiddreads.MuffinEMU), Every build of main is published as a numbered release going up by 0.1 — after .9 comes the next whole number: 1.0, 1.1 … 1.9, 2.0.

3. Turn on JIT

The AArch64 recompiler needs two things at once. You need both, or MuffinEMU uses the interpreter.

  1. Attach a JIT enabler — StikJIT, or the JIT attach that SideStore or LiveContainer provides itself.
  2. Turn the recompiler on in Settings > CPU.

Without both, MuffinEMU uses the interpreter, which is much slower. Settings > CPU shows which one this launch is using and why.

If a game glitches, desyncs or crashes, Settings > CPU has a Favour accuracy option — slower, but worth trying before assuming something else is broken. Restart the game after changing any CPU setting; they do not apply mid-session.

4. Add keys.txt

Encrypted retail games need keys.txt dumped from your own Wii U. Homebrew does not.

MuffinEMU does not include keys. Use the keys.txt from your own Wii U.

Drop the file into the keys folder MuffinEMU creates in the Files app — under the app's own name, since file sharing is enabled — or import it from Settings. A file dropped in mid-session is picked up before the next key read, so no relaunch is needed.

Encrypted game folders

A game folder made of title.tmd, title.tik, title.cert and encrypted .app / .h3 files works too, in Files > MuffinEMU > Roms or through the folder importer. It is decrypted with the title key in its own title.tik, so it needs no keys.txt. Every .app file listed by title.tmd has to be present; file-name case does not matter. If a file is missing or the ticket doesn't fit, MuffinEMU names the problem when you start the game.

A parent folder with separate subfolders for the game, its update and its DLC (each with its own title.tmd) is recognised: the game is the library entry and the update and DLC are used when it starts.

MoltenVK

The Vulkan renderer can use MoltenVK 1.4.3 (default) or 1.2.8 — Settings > Graphics. The choice applies on the next launch. Metal, the default renderer, does not use MoltenVK.

Building from source

CI is the build: .github/workflows/build-ios-app.yml runs the whole thing on a macOS runner. By hand, on a Mac with full Xcode:

git clone --recursive https://github.com/MuffinEMU/MuffinEMU.git
cd MuffinEMU
cmake -S . -B build-ios -G Ninja \
  -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_SYSROOT=iphoneos -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=15.0 -DVCPKG_TARGET_TRIPLET=arm64-ios \
  -DBUILD_HEADLESS_DYLIB=ON -DCMAKE_MACOSX_BUNDLE=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-ios --target CemuBin
mkdir -p build-ios/out && cp -R "$(find build-ios bin -type d -name Cemu.framework -not -path '*/CMakeFiles/*' | head -n1)" build-ios/out/
cd src/ios && xcodegen generate
xcodebuild -project MuffinEMU.xcodeproj -scheme MuffinEMU -sdk iphoneos -configuration Release CODE_SIGNING_ALLOWED=NO build

The bridge and its glue compile into Cemu.framework together with the core, against the core's own headers. The Xcode app compiles Swift only and embeds that framework.
