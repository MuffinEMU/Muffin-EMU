Installation

iPhone and iPad, iOS 15 or later. There are two builds, and picking the wrong one is the most common install problem — so start with which installer you use.

On this page

  • 1. Pick your build
  • 2. Install it
  • 3. Turn on JIT
  • 4. Add keys.txt
  • MoltenVK
  • Building from source

1. Pick your build

Two IPAs are published with every release, because the two install paths need genuinely different builds. Pick the row that matches how you install apps.

SideStore / AltStore / LiveContainer

MuffinEMU.ipa

  • Re-signed with your own Apple ID at install.
  • Unsigned on purpose — the installer signs it.
  • JIT entitlements are stripped by that re-sign, so you attach JIT separately with StikJIT, or SideStore's or LiveContainer's own JIT attach.

TrollStore / jailbroken

MuffinEMU-fakesigned.ipa

  • Ad-hoc signed — no certificate, no team ID.
  • JIT entitlements are embedded in the IPA itself.
  • Most tools will still call this "not signed". That is what ad-hoc signing looks like, not a fault.
Why two files

A SideStore re-sign strips entitlements, so shipping only the fakesigned build would break SideStore users, and shipping only the unsigned build would cost TrollStore users their embedded JIT. Hence one source for each.

2. Install it

SideStore / AltStore / LiveContainer

Add to SideStore Add to AltStore

Or add the source by hand: https://kiddreads.github.io/MuffinEMU/apps.json

TrollStore / jailbroken

Add the source: https://kiddreads.github.io/MuffinEMU/trollstore.json

Or download MuffinEMU-fakesigned.ipa directly from the latest release.

MuffinEMU uses its own bundle identifier (com.kiddreads.MuffinEMU), so it installs next to Muffin rather than replacing it. Every build of main is published as a numbered release going up by 0.1 — after .9 comes the next whole number: 1.0, 1.1 … 1.9, 2.0.

3. Turn on JIT

The AArch64 recompiler needs two things at once, and missing either one silently drops you to the interpreter.

  1. Attach a JIT enabler — StikJIT, or the JIT attach that SideStore or LiveContainer provides itself.
  2. Turn the recompiler on in Settings > CPU.

Without both, MuffinEMU falls back to the multi-core PowerPC interpreter automatically. That is much slower, but it is not a failure state — and Settings always states which mode a given launch actually got, and why, rather than failing silently. Check there before assuming something else is wrong.

If a game glitches, desyncs or crashes, Settings > CPU has a Favour accuracy option — slower, but worth trying before assuming something else is broken. Restart the game after changing any CPU setting; they do not apply mid-session.

4. Add keys.txt

Encrypted retail games need keys.txt dumped from your own Wii U. Homebrew does not.

MuffinEMU ships no keys, derives no keys, and has no way to obtain a key it was not given.

Drop the file into the keys folder MuffinEMU creates in the Files app — under the app's own name, since file sharing is enabled — or import it from Settings. A file dropped in mid-session is picked up before the next key read, so no relaunch is needed.

MoltenVK

The Vulkan renderer can use MoltenVK 1.4.3 (the default) or 1.2.8, the build 64Touch uses — Settings > Graphics. The choice applies on the next launch. Metal, the default renderer, does not use MoltenVK at all.

Building from source

CI is the build: .github/workflows/build-ios-app.yml runs the whole thing on a macOS runner. By hand, on a Mac with full Xcode:

git clone --recursive https://github.com/kiddreads/MuffinEMU.git
cd MuffinEMU
cmake -S . -B build-ios -G Ninja \
  -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_SYSROOT=iphoneos -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=15.0 -DVCPKG_TARGET_TRIPLET=arm64-ios \
  -DBUILD_HEADLESS_DYLIB=ON -DCMAKE_MACOSX_BUNDLE=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-ios --target CemuBin
mkdir -p build-ios/out && cp -R "$(find build-ios bin -type d -name Cemu.framework -not -path '*/CMakeFiles/*' | head -n1)" build-ios/out/
cd src/ios && xcodegen generate
xcodebuild -project MuffinEMU.xcodeproj -scheme MuffinEMU -sdk iphoneos -configuration Release CODE_SIGNING_ALLOWED=NO build

The bridge and its glue compile into Cemu.framework together with the core, against the core's own headers. The Xcode app compiles Swift only and embeds that framework.
