Screen Layout

The Wii U has two screens — the TV and the GamePad (DRC). Two related but genuinely different systems decide where each one goes.

Cemu models the TV and GamePad as two separate windows, each with its own Metal layer. Desktop Cemu can open a second OS window for the GamePad; on iOS the two systems below cover the two situations that replaces: sharing one physical screen, and routing to a real second one when it exists.

Screen Layout (this device's own screen)

Settings > Display > Screen Layout, ported from MeloCafe — it already had exactly this, and MuffinEMU didn't until it was brought over.

ModeWhat it does
Single Screen Only the selected screen renders. A swap button switches between TV and GamePad.
Adaptive (Both Screens) TV and GamePad automatically adjust: stacked in portrait, side by side in landscape.
Both Screens (GamePad Top Right) A small GamePad appears at the top right in its own column beside the TV view.

Single Screen is the default. While it's active, a "Show Swap Button (TV ⇄ Pad)" toggle controls whether the in-game swap button appears — it's the only mode where exactly one screen is visible at a time, so it's the only one where swapping means anything.

External display routing

Separate from the above: which of the two screens goes to a genuine second physical display, when one is actually connected. Inert without one. Three placements, and MuffinEMU's log always records which was chosen and why:

PlacementWhen it appliesResult
dualScreen An external display is connected and the app has its own window scene for it TV goes to the external display, GamePad stays on the device — both get a real layer
deviceMirrored An external display is connected, but the app has no scene of its own for it (plain AirPlay/screen mirroring) TV stays on the device (and reaches the external display only through the mirror). GamePad screen is not rendered.
deviceOnly No external display TV on the device, GamePad screen not rendered

Honest status: only deviceOnly is exercised every launch on a plain iPad. dualScreen is written against the real UIKit API, but nobody has run it with a display actually attached, and the app ships no external-display scene configuration — so in practice, connecting a display today is expected to land on deviceMirrored, not dualScreen. Don't assume true dual-screen output works until a device log shows placement=dualScreen.

When a real external display is in charge of the TV screen, on-device Screen Layout steps back for that screen — the two systems are never both "in charge" of the same screen at the same moment, which is why each gets its own swap setting (TV ⇄ Pad for the external-display case, a separate one for on-device Single Screen) rather than sharing one.
