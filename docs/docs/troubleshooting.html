Troubleshooting

The failures that actually happen, each answered in the first line. If none of these match, the last section covers what to attach to a bug report.

On this page

  • A game won't launch
  • It's running on the interpreter
  • A game glitches or crashes
  • A save state won't load
  • "Not signed" on install
  • Nothing on my TV
  • Collecting logs

An encrypted game does nothing when I try to launch it

You need keys.txt, dumped from your own Wii U.

Put it in the keys folder MuffinEMU creates in the Files app, or import it via Settings. Without it, encrypted games simply will not run — homebrew and unencrypted content are unaffected either way. A file dropped in mid-session is picked up before the next key read, so no relaunch is needed.

The game seems to be running on the interpreter, not the recompiler

Check Settings > CPU first — it always states which mode this launch got, and why.

The recompiler needs both a JIT enabler attached (StikJIT, or SideStore's or LiveContainer's own attach) and the recompiler switch on in Settings > CPU. Missing either one, MuffinEMU falls back to the interpreter automatically rather than failing. See JIT requirements.

A game glitches, desyncs, or crashes

Try Settings > CPU > "Favour accuracy", then restart the game.

It is slower, but it trades speed for correctness on titles that do not get along with the fast path. CPU settings do not apply mid-session, so the restart is required, not optional.

If a game needs geometry shaders or RECTS draws, note that a GPU without mesh shader support — the A12Z among them — emulates those with compute passes, which is not always a perfect substitute.

A save state won't load

This is refused on purpose if the game was quit, relaunched, or the app restarted since the save was taken.

A save state only loads back into the exact same running instance it came from. Loading is refused outright unless the running title's ID, thread list, and memory layout all match the save exactly — see Save States for the full reasoning. For anything that needs to survive between sessions, use the game's own normal saves.

After loading a save state, something looks briefly wrong on screen

Expected, and not lost progress.

A texture or shader that changed since the save may flash its old contents for a moment, until the game's own next draw call refreshes it. See Save States for why GPU state is deliberately not part of what is captured.

TrollStore or an installer says the IPA is "not signed"

Expected for MuffinEMU-fakesigned.ipa — that is what ad-hoc signing looks like.

Ad-hoc signing has no certificate or team ID, so most tools describe it that way. Use that file for TrollStore or a jailbroken device. MuffinEMU.ipa is the plain unsigned build for SideStore/AltStore/LiveContainer, which re-sign it themselves at install. See Installation for which one you need.

Nothing shows up on my TV or second display

True dual-screen output has never been confirmed working on real hardware.

Not confirmed on hardware

The code path exists and is written against the real API, but is expected to fall back to screen-mirroring behaviour — TV screen only, mirrored — rather than routing the TV and GamePad to separate displays. See External display routing for the full breakdown of what is and is not confirmed.

Collecting logs before filing a bug

Two files matter: the running log.txt, and Documents/CemuCrashLog.txt.

CemuCrashLog.txt is a checkpoint trail written with a raw synchronous write, specifically so it survives even an abrupt process termination. If the app never got far enough to open a log at all, there may be no CemuCrashLog.txt to send — say so in your report rather than assuming one exists.

Attach both when you can, and open an issue at github.com/kiddreads/MuffinEMU/issues.
