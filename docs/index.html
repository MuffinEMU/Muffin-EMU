Muffin

Wii U emulation on iOS — in the open.

🧁Install

Two sources, because the two install paths need different builds. Pick the one that matches how you sideload.

iPhone and iPad, iOS 15 or later. Landscape.

SideStore / AltStore / LiveContainer

These re-sign with your own Apple ID at install, so they take the standard unsigned build.

Add to SideStore Add to AltStore
https://kiddreads.github.io/cemu-ios-muffin/apps.json

TrollStore / jailbroken

Takes the ad-hoc signed build, with the JIT entitlements actually embedded — which is what lets the recompiler get executable memory. A SideStore re-sign would strip them, which is why this is a separate source. The interpreter needs none of this, and it is what every confirmed run so far has used.

https://kiddreads.github.io/cemu-ios-muffin/trollstore.json

Or grab Cemu-fakesigned.ipa directly from Releases.

Which file is which? Cemu.ipa is unsigned on purpose. Cemu-fakesigned.ipa is ad-hoc signed. Ad-hoc signing has no certificate and no team ID, so most tools describe it as “not signed” — that is what fake-signing is, not a fault. To tell them apart: codesign -dv Payload/Cemu.app reports Signature=adhoc for the fake-signed one.

📋Where this actually is

One retail game has been confirmed running at a playable speed, on one device. FAST Racing NEO, on an iPad Pro (A12Z, iPad8,11, iOS 26.6.1). That is the whole of the evidence: one game, one device, a picture and a framerate — not a confirmed controller and not a confirmed sound.

Cemu's real C++ engine, built for arm64 iOS Ships as an installable IPA Titles boot and run A picture reaches the screen One game playable, one device Correct picture in every scene: not established Touch + MFi controllers wired, unfelt Audio never confirmed on a device

Measured on that device, over 66 seconds, so a later log can be compared against it rather than remembered:

Metal: GPU 'Apple A12Z GPU' | Apple family yes | Metal3 no | mesh shaders no JIT check: mmap(MAP_JIT, executable at map time) refused (errno 22) ... Forcing the interpreter Emulated timebase: shift 6 (0.125x real time) Heartbeat: 66.2s - 5844241011 instr (+154196171, 50.00 MIPS), GX2 frames 2426 (+10, 3.24 fps) Heartbeat: 69.3s - 6433282371 instr (+589041360, 190.64 MIPS), GX2 frames 2496 (+70, 22.65 fps) Memory: 2416 MB in use, 2191 MB of headroom left before iOS kills this process

The on-screen framerate in that session swung between 21 and 61 FPS inside a single scene. The heartbeat's own frame counter disagrees with the overlay, and that has not been run down yet.

⚡The recompiler, and the interpreter that did the work

Every confirmed run of this port has been interpreter-only. Not by choice: the JIT capability probe asked for PROT_EXEC at mmap() time, which is the x86_64 shape of that API and something iOS arm64 never grants, so it failed with EINVAL on every launch — including fake-signed TrollStore builds with the entitlements genuinely embedded. The recompiler was unreachable the whole time.

Which makes the number above worth stating plainly rather than hiding: the interpreter alone, at an eighth of real time, measured 50–190 MIPS on a 2020 tablet and got to a framerate the game was played at. The 0.125× clock was a consequence of the failed probe, not a separate setting.

The probe now tests what the platform actually permits. That makes the recompiler reachable; it does not make it correct. It has still never been proven to execute a PPC instruction correctly on device, it stays off by default in Settings, and that fix shipped in v5.2-jit-and-rects.

Both CPU modes are first-class here. “Use the JIT” is not a fix for anything in this project.

🔧Known wrong, and why

  • Post-processing was dropped on every A12Z-class device, always. Geometry-shader/RECTS emulation existed but could never switch on — the renderer latched the flag at construction, and the only code that set it ran afterwards. The device log counted 44,001 dropped draws, 39,098 of them RECTS, which is the full-screen copy and post-processing path: the tonemap and composite chain never ran. Now enabled; not yet confirmed by a device log taken after the fix.
  • The Metal binary archive is deliberately disabled. It matched cached entries to pipelines by rules the code cannot inspect, silently ran the wrong compiled shader, and is what broke rendering across the whole v4 release line. Off behind a named constant, with the evidence and the re-enable test written at the site. Costs first-launch compile time and nothing else.
  • BC1–BC5 textures are decompressed on the CPU. No Apple GPU up to and including the A12Z has block-compression hardware, and Metal aborts the process rather than refusing the descriptor. Costs CPU per upload and memory per texture — BC1 goes from half a byte per texel to four — on a device already sitting at 2416 MB.
  • Shader compilation is the stutter. One session compiled 1991 new shaders (1699 async) and 25 pipelines. The Wii U only reveals a shader when it first draws with it, so no cache avoids the first encounter; async compile turns the hitch into something appearing late rather than removing the work.
  • 282 million idle spins in 66 seconds, still climbing ~19M per heartbeat. A core alive with nothing runnable, spinning rather than sleeping. Cause not established.
  • Audio has never made a confirmed sound on a device. The CoreAudio backend is real and is initialised on iOS now. Nothing confirms output. It will not be claimed until something does.
