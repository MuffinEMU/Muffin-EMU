MuffinEMU is three layers: a SwiftUI app, a plain-C bridge, and the emulator core. The app never touches the core directly.

## Build products

- **`Cemu.framework`** — the core plus the bridge, built with CMake (`-DBUILD_HEADLESS_DYLIB=ON`). The bridge is compiled into the framework so it builds against the core's own headers.
- **`MuffinEMU.app`** — generated by XcodeGen from `src/ios/project.yml`. It compiles Swift only and embeds `Cemu.framework` and both MoltenVK builds.

CI checks that every function declared in `CemuBridge.h` is exported by the framework before the app is built, so a missing bridge symbol fails early instead of as a linker error inside `xcodebuild`.

## CPU

The bridge always sets an explicit CPU mode. The recompiler is used only when the user has enabled it and the process is being debugged (`CS_DEBUGGED`), which is how iOS JIT enablers grant writable-and-executable memory. Otherwise the interpreter runs.

## Graphics

- **Metal** is the default renderer. Render views are backed by a `CAMetalLayer` (`MetalLayerView` in `DisplayRouter.swift`), and the core draws into that layer directly. The layer's scale comes from the bridge's window info rather than from the layer, so UIKit changing `contentsScale` cannot desynchronise the drawable size.
- **Vulkan** runs through MoltenVK. Two builds ship embedded but unlinked, 1.4.3 and 1.2.8; the bridge sets `MUFFIN_MOLTENVK_PATH` before initialising and the core loads that one.
- GPUs without BC texture support decode BC textures on the CPU.

## Input

The on-screen pad reports button and stick state through `cemu_bridge_set_button_state()` and `cemu_bridge_set_stick_axis()`. That state feeds the core's GameController input provider, so the on-screen pad and an attached controller work side by side.

Button bindings are persisted in `controllerProfiles/` on the device. When the GamePad profile loads with any button unbound, the core fills the missing bindings with defaults and leaves the user's own remaps alone. Settings › Diagnostics › *Show controls diagnostic* shows the mounted pad, touch and input counts, and the number of bound buttons.

## Releases

`.github/workflows/build-ios-app.yml` builds, verifies and publishes both IPAs. Each commit carries a `Release-note:` trailer written for players, and the release notes are assembled from those trailers. Changes to Markdown files and to `docs/` do not trigger a build.
