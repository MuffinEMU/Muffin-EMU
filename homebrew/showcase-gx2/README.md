# MuffinEMU Showcase (GX2)

`showcase-gx2.rpx` is an original Wii U homebrew program that exercises MuffinEMU through the
**GX2 graphics path**: compiled shaders, vertex buffers, textures, render targets, and the TV and
the GamePad as two separate GPU targets. The companion `homebrew/showcase` draws on the CPU through
OSScreen; this one is what runs when a game talks to the GPU, so together they cover both display
paths.

Everything is generated by code at startup. There is no image, model, font or audio file, and no
Nintendo asset. The RPX needs nothing next to it.

## Build

CI only: `.github/workflows/build-showcase-gx2-rpx.yml` (devkitPPC container, wut's sample Makefile).
It compiles `source/shaders/*.vs|ps` with CafeGLSL's `glslcompiler` (the same pinned, hash-checked
binary the bench uses), bakes the result into C headers, builds and verifies the RPX, and uploads it
as an artifact. A manual run with `publish=true` also creates a `showcase-gx2-<sha>` pre-release.

## Design notes

- **One renderer.** `gfx.c` is a small immediate-mode layer: one vertex format, one scene shader
  (texture x vertex colour, fog, tint) and one full-screen shader. Geometry goes through a pool of
  GX2R vertex buffers, double-buffered per frame.
- **Uniforms are copied.** `GX2Set*UniformBlock` passes an address to the GPU, so every draw copies
  its uniforms into a persistent 256-byte-aligned ring instead of pointing at the stack.
- **No `sinf`/`cosf` pairs.** GCC folds them into `sincosf`, which this target's newlib lacks. All
  code calls the `fsin`/`fcos` wrappers in `gfx.c`.
- **Music.** `synth.c` renders a 16-bar loop (four channels, 24 kHz, about 29 seconds) on a worker
  thread on core 2 while the menu is already running. `synth.c` has no console dependencies, so it also
  builds on a PC for testing.
- **If audio output does not start**, the visuals fall back to the wall clock and keep reacting to
  the (still synthesized) music.
